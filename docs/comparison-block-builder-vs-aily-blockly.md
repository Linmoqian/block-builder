# Block Builder vs Aily Blockly — 详细对比分析

## 一、项目概览

| 维度 | Block Builder | Aily Blockly |
|------|--------------|-------------|
| **版本** | 0.1.0（开发中） | 0.9.53（Alpha） |
| **定位** | 可视化神经网络构建工具 | AI 辅助硬件积木编程 IDE |
| **目标用户** | 深度学习研究者/工程师 | 非专业嵌入式开发者/教育用户 |
| **开源协议** | MIT | GPL |
| **输出产物** | PyTorch 代码、YOLO YAML | C/C++/Arduino 固件 |
| **所属生态** | 独立项目 | [aily Project](https://aily.pro) 生态 |
| **官网** | — | https://aily.pro |

## 二、技术栈对比

### 2.1 前端框架

### 2.2 积木/编辑器引擎

| 维度 | Block Builder | Aily Blockly |
|------|--------------|-------------|
| 核心引擎 | @xyflow/react 12 (React Flow) | Google Blockly 11 |
| 编辑范式 | 节点-连线图（自由拓扑） | 积木块拼接（结构化编程） |
| 代码编辑器 | Monaco Editor（YAML 预览） | Monaco Editor（完整代码编辑） |
| 终端 | 无 | xterm.js |

| 图表生成 | 无 | Mermaid 11 |

**关键差异**：Block Builder 使用 React Flow 构建自由形式的 DAG 图编辑器，节点之间通过端口连线表达数据流；Aily Blockly 使用 Google Blockly 做传统的积木块嵌套拼接，更接近 Scratch 风格。

5. 导出 → yamlExport / pytorchExport 生成代码

## 七、可互相借鉴的方面

### Block Builder 可借鉴 Aily Blockly

1. **AI 代码生成**：MCP 协议集成，根据图结构自动补全/优化网络
2. **项目管理**：工程化项目结构，支持多项目管理
3. **库管理器**：类似预设模板的可扩展模块市场
4. **终端集成**：内置终端用于运行生成的 PyTorch 代码
5. **多编辑器**：图编辑器 + 代码编辑器双模式切换
6. **自动更新**：Tauri 的 updater 插件
7. **新手引导**：onboarding 引导流程，降低学习门槛

### Aily Blockly 可借鉴 Block Builder

1. **形状推断**：类型系统 + 自动推导，可应用于引脚类型检查
2. **图验证**：环检测、断连检查等图论验证算法
3. **导入/导出**：标准格式 (YAML) 的双向转换
4. **轻量桌面**：Tauri 替代 Electron，减小包体积和内存占用
5. **自动布局**：DAG 层级布局算法用于连线图的自动排版
6. **撤销/重做**：基于历史栈的完善实现（50 步历史）
7. **模型统计**：参数量 + FLOPs 实时估算，提供量化反馈

## 八、总结

两个项目在"可视化编程"这一核心理念上相通，但领域和技术路线截然不同：

- **Block Builder** 是一个聚焦的深度学习工具，以 React Flow 图编辑器为核心，通过 Graph IR 中间表示实现神经网络拓扑的可视化构建和代码生成。架构精简，采用 Zustand 统一状态管理，具备完善的形状推断、图验证、模型统计能力和单元测试覆盖。
- **Aily Blockly** 是一个全功能硬件开发 IDE，以 Google Blockly 积木编程为核心，覆盖从编程、编译、烧录到调试的完整硬件开发生命周期。功能丰富，深度集成 AI 能力和云端服务，产品化程度高。
